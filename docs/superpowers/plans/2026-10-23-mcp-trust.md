# MCP Trust and Execution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discover and run only explicitly trusted MCP servers, while keeping server trust separate from per-call auto-approval and removing provider credentials from child environments.

**Architecture:** Validate the shared `mcpServers` map in the IDE host, store trust in editor `globalState` against a stable fingerprint of server name/executable/arguments, and obtain trust before calling MCP discovery because discovery launches a process. Integrate the pinned MCP tools only after a separate reviewed shared-tools change exposes environment injection; never edit the sibling CLI or generated vendor files from this checkout.

**Tech Stack:** TypeScript, VS Code `globalState` and modal UI, pinned `@moderado/contracts` / `@moderado/tools`, Vitest fake stdio process fixtures.

**Spec:** `docs/superpowers/specs/2026-10-23-profile-mcp-skills-acceptance-design.md`

## Global Constraints

- Server trust is required before discovery or launch, regardless of the Use MCP servers auto-approval setting.
- Show the exact executable and argument list and explain the server's OS-level access; do not call an MCP server jailed.
- Provider credentials, including `MODERADO_<ID>_API_KEY`, must not enter MCP child environments.
- Do not edit the sibling CLI or generated `vendor/moderado` files; do not add a runtime dependency.
- If the reviewed environment-injection API is not present at the pinned revision, do not launch MCP processes.
